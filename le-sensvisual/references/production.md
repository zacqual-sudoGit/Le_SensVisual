# Realise the complete visual design

Resolve the core's [visual decisions](../SKILL.md#create-as-one-coordinated-task)
before selecting production. Choose supported methods by their ability to realise
the main and supporting expressions and the task's actual operations. Readable
copy matters in either method; an available renderer alone does not select one.

**Generate the finished image:** brief the complete world, main and supporting
subjects/actions, relationships, reading fields, shared identity and required
copy together. Inspect those expressions, facts and wording in the returned
page, refine as needed and deliver. Retain the actual image through the host's
supported output; no assembly is needed for an already complete image.

**Assemble the finished artifact:** use when combining contributions provides
useful control for the design or required operations. Produce/source the main
and supporting expressions, obtain usable assets, compose them with information,
and inspect the export. New visual PPTX follows [presentations](presentations.md);
other formats use a supported writer. The mechanics below serve this method.

## Resolve the whole canvas and its regions

Set dimensions, viewing size and page jobs. Compose the subject's setting,
people, objects, actions and relationships with calm reading fields. Resolve
main and supporting destinations together before their artwork requests. A
header, sequence and cards can carry complementary parts of the world; a region
can combine a scene, illustrated symbol and copy.

Keep the core's map in working context or, for assembly, the consumed source or
optional [execution record](execution.md). Resolve shared style, colour roles,
lighting/material, icon language and type hierarchy with deliberate regional
variations. Brief useful atmosphere, actions and detail at final viewing scale.

## Produce the artwork and continue its placement

Use exposed host tools and working context. An attachment supplies guidance;
it does not establish filesystem, loader or script access.

Actually call the available image-generation tool for planned new illustrations;
source or reuse suitable existing artwork. Carry each region's subject/action,
benefit and destination into its request and actual result. A simpler pictogram
does not fulfil a planned richer scene or illustrated action. Obtain and inspect
the real asset before dependent placement. Independent layout preparation may
proceed while artwork is being made.

Keep the full result in working memory or a host-exported file before leaving
generation. Read its actual return schema: a file path can be loaded; a data URL
contains the image bytes to save; an opaque asset ID needs the host's supported
export/transfer. Reuse that result for assembly rather than generate a new image
to discover its format. Use the [handoff implementation](execution.md#retain-and-save-the-actual-image-result)
for the portable file bridge. A genuine end-of-turn or transfer limit remains
explicit when no supported continuation exists.

When production encounters a limit, locate the failed operation and recover
the intended contribution through another supported route. Preserve its subject,
action, atmosphere and role in the composition. Report a genuine remaining
shortfall against that original intent.

## Brief and produce the parts under the same design

For assembly, turn each planned destination into an artwork request specifying:

- concrete subjects/actions and the content they reinforce;
- destination dimensions/aspect, focal-subject position and useful detail at final scale;
- shared style/reference, colour roles and any local variation;
- protected copy/icon fields, crop margins and relation to neighbouring layers;
- required transparency, background continuity or detail that survives local fading.

Keep copy the writer will add out of these assembly assets. Select supported output settings for adequate resolution and
the intended aspect; inspect actual dimensions and framing. The writer controls
exact final size/position. Adapt the crop or revise the composition when needed
to preserve meaning. Stating dimensions in a prompt alone does not establish fit.

For example, an illustrative 640x360 preparation-card request could say:
"Illustration for a planned 640x360 card: show a patient gathering appointment
papers on the right, with a calm left reading field and clear upper-left space
for the heading icon. Use the shared warm
clinic style; keep the person and papers inside the crop. Provide the illustration
without labels or numbering." These are the planned slot's needs, not a fixed
layout for other jobs. A separately placed illustrated icon gets its own useful
final-size detail and transparency needs.

Produce independent assets in supported batches or separate calls; follow dependencies where one asset needs an accepted reference or another tool's output. A common style sentence alone may not ensure consistency: supply actual visual references where supported and compare the returned parts together. A group/sheet is useful only if its parts can be cleanly separated at sufficient resolution. The number of visual components does not prescribe the number of generation calls.

The coordinating AI owns the handoff; the user need not manually request
generation, insertion and continuation. Keep three checks distinct:

| Check | Evidence needed |
|---|---|
| Receiver acceptance | Its actual input contract supports this file, upload, asset ID, URL or inline data; obtain the supported result. Passing a parameter or receiving a success message alone does not prove placement. |
| Visible integration | The required contribution appears in the actual delivered canvas at useful scale, crop and contrast, without missing content or a substituted placeholder. An image reference in source/DOM is not visual proof. |
| TYY contribution | The integrated part supplies its chosen world, atmosphere, meaning or relationship and harmonises with its reading field and neighbours. Mere image presence earns no such credit. |

Apply these to required visual and information contributions, not every unused
asset or variation produced. When binding fails, use [tools](tools.md) to locate
the unsupported operation and choose an actual supported route. A self-contained
HTML file still needs accessible image bytes; changing format does not establish
a repair or fulfil a different requested deliverable.

Confirm the actual subject/action before placement; cropping cannot introduce
an absent action. Repair the affected contribution while retaining its benefit.

## Assemble and harmonise the complete canvas

Place the real artwork, illustrated symbols and information according to the map. Treat related layers as regional compositions: for example, a faded scene beneath an icon and text, with its subject still visible and quiet space protecting the words. Fit crop, scale, position, contrast and opacity together; enlarging or fading an asset can change its meaning. Build connected states, diagrams and charts with their true geometry, values and labelled relationships.

Inspect all contributions together at intended viewing size. Adjust illustration treatment, scale, colour, detail, spacing and reading fields across the canvas; replace an incompatible asset where placement adjustments cannot resolve it. Review the supporting regions as well as the main scene. Carry the visual world through relevant body messages and individual cards. Also reconsider worthwhile opportunities absent from the plan.

Use [review](review.md) for visible TYY achievement, then factual, reading and
delivery checks. Continue needed producer-owned corrections within the task;
separate development benchmarks require their own authorization.

## Apply the chosen medium

When assembling, use [canvas assembly](native-authoring.md) for layout/geometry and [presentations](presentations.md) for deck mechanics. Use [assets](assets.md) for needed extraction/transparency. Keep generated signs, maps, procedural arrows and technical depictions factually checked. Give different pages their assigned responsibilities; repeating the whole task without page roles can yield competing complete-story variants.

When editability is requested, provide editable text, data and objects for the specified operations. Preserve the illustration quality around them; disclose which artwork details remain pixels. A finished page image wrapped in HTML or PPTX does not establish editable information. Provide required copyable code/data companions without letting reference detail displace the visual explanation.

## Conditional: convert existing accepted work

Use this branch when the user asks to convert an existing artifact. Its accepted composition and artwork provide the reference for requested changes. ## Complete and deliver

Inspect each delivered format's actual appearance, proportions, page count and required operations. A montage's bands are not automatically finished pages; source appearance does not verify a changed export. Resolve consequential omissions before delivery and disclose persistent limits.

If the host displays generated artwork before the document exists, continue assembly using the same map and actual assets. If a tool ends the turn or requires user input to continue, state that specific limitation and next action. One user task can contain many tool calls and internal passes; it cannot override the host's execution limits.
