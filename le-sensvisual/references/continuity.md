# Optional continuity record

Use for long work, interrupted production or transfer to another model/host. Reuse an existing brief/record; no compulsory filename, phase machine, JSON schema or local evidence directory.

Keep only what the next producer needs:
- user purpose/audience, required facts and requested format/editing operations;
- settled composition, visible subjects/actions/relationships, page jobs and intended proportions;
- actual assets/artifacts and relevant source version;
- what was built/inspected, TYY strengths and missing expressions, separate content/production limits and assistance;
- current task and next action.

Evidence can be an accessible local path, attachment, URL, tool result or native project/asset ID. A filename or inaccessible ID does not establish inspection. Separate requested, planned, produced and verified states. Do not reuse an old render as proof of changed output.

On resume, recover the recorded decisions and actual tool capabilities, then continue. If multiple skill copies exist, identify the authoritative path/version before evaluation or installation. Do not silently substitute an installed old copy for a requested candidate. Self-review is not independent review.

When moving between hosts, carry the resolved visual decisions and actual usable
assets, not assumptions about Codex paths, reference loading or tool exposure.
Re-establish the new host's capabilities and continue the same intended design.
An old host's successful run does not establish execution in the new one.

When using the [managed execution path](execution.md), its production record and
file-bound receipts already carry those details. Continue that record rather
than creating another state system; stale artifact/capture hashes need renewed
inspection. Its JSON schema is conditional on using those helpers.
