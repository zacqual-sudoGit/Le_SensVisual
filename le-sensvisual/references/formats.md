# Fit the requested medium

Read the relevant section. The core's visual priorities and composition brief govern each medium.

## Slides and decks

Assign each slide a communication job and a complete viewing-sized canvas. Use an appropriate aspect ratio; widescreen is a useful default for an unspecified deck. Compose artwork and information to that canvas. A subject-rich cover establishes identity; body pages must express their own messages through suitable visuals and relationships.

New visual PPTX creation follows [presentations](presentations.md)'s composition → artwork → actual assets → assembly → inspection sequence. Format mechanics implement that composition. For slide-image delivery, use [production](production.md)'s selected method and inspect the finished images.

Carry the same visual ambition into every requested format. Several requested formats can share intent and assets while adapting the construction. A slide export is a valid image delivery when requested, but it is not an independent image-generation comparison in an evaluation.

For requested editable slides, place the main audience copy, timings, labels and figures in editable objects unless a narrower operation is specified. Illustrations can remain raster. Inspect placement, crop, reading size and the native objects actually delivered. Putting a flattened information page on a slide provides image placement editing only for that page's contents.

## Posters, teaching sheets, editorial and PDFs

Choose density and attention order for the job: invite action, explain, compare or provide reference. Compose illustrations, relationships and calm reading fields together. Make logistics and consequential uncertainty easy to find; review at intended viewing size.

For teaching, lead with the central idea in a recognisable worked situation. Connect code/formulas to relevant objects, actions, mechanisms or data states. Use subject context and visual materials for identity and atmosphere. Distinguish this explanation from syntax definitions, complete programs and reference detail, preserving required content and usable reading space. Technical density does not require uniform text panels or unrelated scenery.

## Diagrams and charts

Identify the real relationship before geometry. Check parts, endpoints, direction, boundaries and intermediate changes. Sources that establish facts do not necessarily establish a drawable mechanism. Use reliable source imagery and checked diagram geometry to depict the process truthfully.

Label conceptual depictions where readers could mistake them for measured data or surveyed geometry. Preserve real scales and values. Use actual editable data or semantic objects for promised chart or relationship edits.

Distinguish thematic illustration from technical depiction. Illustrated stage markers can supply recognition, atmosphere and memory while labels/connectors carry the exact sequence. A system diagram must depict its actual connections and limits. Coordinate generated artwork with precise labels/geometry where useful, retaining one visual identity; see the [Slide 5 construction example](production.md#worked-construction-example-tyy-slide-5).

## Interfaces

Compose around user tasks, states and established components/design rules. Integrate topic identity with actionable hierarchy, navigation and relevant error/empty/loading states. Preserve accessibility, focus, labels and touch targets. Use authentic interface evidence where available; a screenshot does not establish adoption or performance. Inspect rendered states and relevant viewports.

## Motion

Use timing, transitions and camera/composition to explain the message or establish experience. Keep essential information readable long enough, and provide accessible/static alternatives where appropriate. Inspect actual playback for the produced sequence, timing and framing. A still preview verifies only that still.
