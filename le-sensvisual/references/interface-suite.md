# Interface and design-system suite

Use for an actual interface, continuing product, component system or requested technical review. Keep the parent TYY design authority. These tools do not make every poster a website.

## Resolve facts, system and surface

Read actual product facts/constraints, supplied assets, existing tokens/components and rendered states. Preserve a coherent incumbent identity unless redesign is requested. Keep durable product facts in PRODUCT.md when useful; record actual reusable visual decisions in DESIGN.md; keep one surface's strategy in its own brief. Do not invent implemented components or promote local choices into global bans.

Use [new-work](../modules/impeccable/reference/new-work.md) for new interface work. Select a practical mode: persuasion, working tool, reading/explanation or experience. Reading comfort and familiar controls remain valuable; the subject's world can still contribute inside the information, not only in the header.

## Engine operation

`python scripts/visuasense.py setup --engine` downloads the pinned platform binary with recorded checksum verification. It installs no hooks. `engine <verb>` exposes existing engine operations; preserve cwd at the user's project. `detect <targets>` returns single-copy findings with technical/style indexes in a bounded packet; `--offset`/`--limit` pages additional findings, and explicit `--raw` preserves complete diagnostics. All 59 detector rules remain available; contextual aesthetic findings are not universal bans.

The full engine supports context/signals, design parsing, concept/catalogue exploration, palette helpers, region/spec/font/diff tools, build phases, component review, critique storage, live sessions, hooks and doctor/pinning helpers. See [tools](tools.md) for commands, dependencies and limits. Some verbs contact external services or modify host/project state; use them only for the current authorized task. For image generation, prefer an available host image-generation tool; a separate image API requires configured credentials and authorization. Use the generated assets in the same coordinated interface production task.

## Review

Inspect actual views, content extremes and relevant states. Judge visible TYY benefits and consequential omissions first; separately verify facts and technical operation. Aesthetic patterns such as a familiar font, illustrated object, cream field, eyebrow or card are legitimate when they serve the resolved design. Verify a detector's finding in context rather than remove meaning to clear it.

Use independent review when authorized/available; otherwise label sequential self-review honestly. Do not force a full review process for a narrow edit. Keep repairs within scope and inspect affected output. Strict fidelity gates apply to the selected accepted-reference path, not every fresh interface.
