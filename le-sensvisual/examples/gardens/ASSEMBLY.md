# Gardens: one design, several tools, one delivered slide

This is the unchanged rc.3 visitor-planning proposal result, retained as a
construction reference. It is not a new test, an official Gardens service or a
universal slide template. Preview/map/prompt stay in the main installation;
the optional `gardens-construction` companion or offline bundle retains the PPTX,
asset sheet and separated crops. Use the resource resolver for their actual path.

## Visible decisions worth transferring

The setting is distributed: a Gardens panorama establishes place; visitors
planning together establish the experience; four small illustrated objects make
planning difficulties recognisable; each audience card has a distinct scene as
well as a vector symbol. Calm paper fields allow the native wording to remain
readable. Consistent ink/watercolour, botanical detail and four audience accents
unite the regions. The smaller scenes carry the world beyond the main image.

The four audience needs/values are proposal hypotheses, not research findings.
This static audience page needs grouping; it does not need an invented process
arrow or invented outcome evidence. Transfer these judgments to a new subject,
choosing its own world and useful regional opportunities.

The retained artwork prompt is a historical tool request, not new instructions
for every task. Its text-free artwork condition supported native copy in this
particular editable slide; it does not require all Le_SensVisual work to use overlays.

## What actually happened

1. The producer planned the supplied arrangement and shared visual direction.
2. One image-generation request produced a coordinated sheet with a header,
   anchor, four illustrated problem objects and four audience scenes. The actual
   returned image, not the requested resolution, determined the extraction.
3. Ten crops became separately placed picture assets. Four audience icons were
   constructed from native vector shapes/paths. Copy and structures were native.
4. One 1280 × 720 design map placed these elements in the slide writer. Card
   scenes, fading, symbols and copy were composed together. The final file
   contains ten picture objects and 46 native shapes, including text/structures
   and the parts composing the four icons.
5. The producer exported PPTX, imported the final file, rendered it and exercised
   native title replacement/restoration in memory. No desktop PowerPoint check
   was performed. The evaluator viewed the render and inspected source/package;
   it did not repair the output.

Warm paper, tropical greens, lagoon blue, terra cotta and ochre coordinate the
materials. In this composition the four accents link audience icons, strips and
labels. Different subjects can need different roles, palettes and arrangements.

## What this example does and does not teach

The reusable method is **resolve complete composition → brief its contributing
artwork → obtain actual assets → assemble with native objects → harmonise and
inspect the delivered result**. Image-generation and assembly tools participate
in the same task. A clean sheet is useful here; independent assets can be better
elsewhere. Do not flatten editable copy to imitate the preview.

The run used a Codex image tool, presentation guidance, a preinstalled authoring
library and rendering support. Their presence is not supplied by this example.
The portable recipe describes equivalent operations without requiring that
private library or claiming the same tools exist in every host. A reference file
helps only if the LLM reads/applies it; it does not train the model or guarantee
understanding. Original host-specific build source remains in the development
evaluation record, not presented as universal runnable code here.

The brief explicitly required this composition and fourteen contributions. This
is reference-led execution evidence, not evidence of spontaneous opportunity
selection, a controlled A/B improvement or performance across ordinary LLM apps.
The unchanged artifact retains reference numbering “04”/“4”; adapt numbering for
new standalone work. All artwork details remain raster; native text, card
structures and icon geometry are editable. Original first-party work is MIT;
third-party terms and credits remain applicable.
