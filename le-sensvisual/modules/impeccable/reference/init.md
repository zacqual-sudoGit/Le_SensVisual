# Establish product context when needed

Use for a continuing product or when missing facts materially affect interface
work. Read actual existing documentation/code before asking questions. Reuse the
current user's brief. A small visual task does not require a product interview.

Capture purpose, audience and jobs, operating context, core capabilities, known
constraints, voice/brand commitments, accessibility/platform needs and available
evidence. Separate confirmed facts from open decisions; never invent outcomes.
Write PRODUCT.md when persistent context is useful. It owns product truth;
DESIGN.md owns durable visual choices; a surface brief owns one page's strategy.

For native work, record actual target platforms and use the platform references.
For greenfield technical choices, use supplied constraints or clarify a material
decision. Do not select a stack merely because a helper is available.

If the user requests design exploration, route to new-work.md. Image-first,
code-first and mixed construction are alternatives chosen for the current job.
Do not store a global comp-first preference by inference. Live setup is optional
for a user-requested local interface workflow; do not enable hooks automatically.
