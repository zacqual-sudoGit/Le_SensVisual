# Route an interface request

A normal task invokes the parent Le_SensVisual workflow and the relevant specialist
reference. Execute the authorized task; a bare invocation or request for advice
calls for a concise, context-aware recommendation, not an automatic scan.

Use the actual brief and existing artifact. The parent interface-suite.md and
CAPABILITIES.json list the available actions. Recommend the few actions that
address a visible need, with a reason. Missing PRODUCT.md or DESIGN.md alone is
not a reason to start an interview. Use init/document when durable context is
useful; critique for design judgment; audit for technical findings; polish for
scoped refinement; live/generate for requested local web variants.

If the optional engine is already available, context/signals and the parent
detect wrapper can provide evidence for relevant web work. Do not assume setup
already ran or install it to populate a menu. Interpret its style flags through
TYY and the resolved design; a clean scan does not establish visual quality.
Native app work uses native tools and platform references, not web detectors.

The `$le-sensvisual <action>` notation is a user request to this skill. Executable
engine verbs instead use `python <skill-folder>/scripts/visuasense.py engine
<verb> ...` from the user's project directory. Neither notation grants missing
host tools, hook installation, publishing or delegation authorization.
