# Visual direction previews

Use when a visible preview would resolve a material design choice, or the user
asks for alternatives. New creation does not require a comp round. A supplied
accepted reference needs no new direction interview. Use the host's actual image
or native rendering tools; do not promise a capability because a command exists.

## Design and render

Read the actual brief, relevant PRODUCT.md/DESIGN.md and current reference when
present. Resolve the visitor's job, subject, focal treatment, supporting visual
opportunities, reading field and whole-canvas composition. Ground it in actual
content and label proposed/example data. For a continuing product preserve its
useful identity; for a redesign identify what the requested change authorizes.

When alternatives help, vary a meaningful uncertainty—topology, hierarchy,
sequence, visual carrier, density or material expression. Choose the number
needed for that decision; a tidy restyling of the same idea adds little choice.
Do not force a new palette, different fonts or departure from a useful identity.

Use each surface's intended proportions. An image prompt describes the complete
surface and required copy, actual subject, useful atmosphere, objects/actions,
relationships and reading areas. Give a reference image a stated role: identity,
material or a specific composition. Avoid accidental copying of irrelevant
reference content. A poster may look like a poster; an interface preview must
show a usable interface. Inspect every returned render for its actual job.

Save useful comps and prompts under the project's chosen asset directory. The
optional engine uses `.impeccable/mocks/`; inspect its build-phase contract before
using engine-managed state. Use image paths in the form the host viewer accepts.
Record provenance without embedding private prompts or credentials in public
assets. A locally authored comp is a design proposal, not evidence of a built app.

## Choose and construct

Show alternatives together when the user needs to choose. Follow an existing
delegation to make routine design decisions; do not introduce a compulsory
approval stop. Never invent a human approval receipt. If using the engine's
explicit human-review workflow, its actual receipt requirements remain real:
record a pending checkpoint when the required user decision is unavailable.

Build a new resolved composition through the parent production/canvas-assembly
recipe. Use [accepted-comp.md](accepted-comp.md) only for an accepted-reference
fidelity task. Keep the same visual intent across canvas choices; conversion is
not the default interpretation of creating an editable artifact.

For that fidelity branch, inventory actual regions and classify by required
appearance and behavior. Preserve detailed artwork with suitable assets, and
keep required text/controls semantic. Match the illustration's intended subject,
material, detail and contribution to the shared world. Clean-asset extraction/regeneration and
alpha inspection follow the parent assets reference. The optional engine's
strict gates retain upstream medium heuristics; see tools.md before applying
them to vector/native TYY work.
